# ADR 0005: explicit provider plans, bounded context and transactional spend

Status: accepted for explicitly approved Phase 5.

Keep the existing LLMProvider stream contract. OpenAI Responses and private Ollama NDJSON normalize to ProviderEvent and the same durable message/SSE transport. Server configuration owns credentials, model identifiers/capabilities/context/tokenizers/prices and private endpoints. Persist sanitized public provider/model definitions in `ai_providers`/`ai_models`; retire removed models without deleting historical attribution. OpenAI metadata probes use its fixed HTTPS models endpoint, and local Ollama probes `/api/show`. Probes never include project source or start generation, and cannot prove usable billing/quota. API now joins the egress network solely for fixed OpenAI metadata probes; data stores and intelligence remain private.

Persist conversation provider mode, preferred model and explicit fallback consent. Backfill legacy conversations to OpenAI; only new conversations with multiple configured providers and cloud permission default to Auto. Local-only policy filters cloud candidates before selection and overrides Auto. Explicit modes never change provider. Snapshot mode/preference/consent/candidate order per request; later preference edits apply only to future requests. Auto can try an available authorized alternative before inference only when consent permits. Once a provider attempt begins, never replay/fallback automatically, even with no text received; explicit retry can cost again. Model disappearance/policy changes are rechecked at queue execution. Historical user/project success and latency are tie-breakers, not a claim of measured model intelligence.

ContextBuilder reserves output, instruction/framing and safety allowances against each configured model window. Count OpenAI text locally using explicitly configured pinned BPE assets; use a conservative UTF-8 byte upper bound when the generation tokenizer is unavailable/unknown (default Ollama). Chat-protocol framing remains an estimate with a safety margin, not a provider-exact request count. Choose whole recent pairs, a ready unverified summary and whole untrusted source/memory blocks; prioritize source for code/symbol queries, memory otherwise. Never buy hidden summaries or truncate code. Record selection/estimated token/reduction metrics with a same-counter full-history baseline. Reject a mandatory prompt that cannot fit. Existing independent embedding profiles stay unchanged.

Reserve estimated maximum API spend atomically under user -> organization -> project locks before every generation attempt, including summaries. `model_calls` owns identity, provider/model, status, token counts, duration, source and pricing snapshot; `usage_ledgers` owns reserved/estimated money. Enforce UTC daily budgets at all three scopes. Unknown prices use conservative configured reservation rates, remaining explicitly unpriced in reporting. Failed/ambiguous provider attempts retain reservations as uncertain; safe pre-inference failures release them. Successful usage settles estimates only when usage/prices are known. No invoice-cost claim, automatic paid retry or paid usage probe. Financial metadata survives project deletion with nullable foreign keys to prevent spend-reset bypass; it never contains prompt/response text. Detailed calls remain creator-private; owners can see authorized project/organization aggregates.

Cache only creator-private, explicitly human-attested successful test evidence. Narrow Phase 5 registration requires project administration rights, successful exit code, test description/result and attestation; server controls actor/time/kind. Never promote generated memory/answers automatically or accept an AI-only verification claim. Exact error signature plus normalized framework/version/dependencies/environment/Git compatibility and a server-derived current repository digest govern reuse. Lock/recheck evidence, index state and membership before atomic cache publication. Invalidation/changed indexed content makes entries ineligible. Manual evidence is not independently executed verification; the Phase 6 general error/verification execution/history pipeline remains deferred.

Tradeoffs: server configuration is authoritative rather than browser-editable secrets; unique model IDs across providers; availability is metadata-only; token framing/unknown local tokenizers and prices are conservative estimates; repositories must be explicitly reindexed for digest invalidation; no fallback after an inference starts; uncertain reservations need operator review or next-day budget reset. Additional cloud adapters, execution sandboxes and comprehensive quality/scale/security evaluation require later approved work.
